# Sign Language Models Directory

## Structure

Each model lives in its own subfolder with a `model.json` config file:

```
models/sign/
├── convert_to_ir.bat          ← Converts ONNX → OpenVINO IR (run once)
├── convert_models_to_ir.py    ← Conversion logic
├── model1/                    ← PointNet Fingerspelling (default)
│   ├── model.json             ← REQUIRED — model configuration
│   ├── model.onnx             ← Original ONNX weights
│   ├── model.xml + model.bin  ← OpenVINO IR (generated by convert_to_ir.bat)
│   ├── labels.json            ← Optional label map
│   └── README.md              ← Model documentation
│
├── model2/                    ← WLASL Pose-TGCN (2000 words)
│   ├── model.json             ← REQUIRED — model configuration
│   ├── wlasl_pose_tgcn.onnx   ← Original ONNX weights
│   ├── wlasl_pose_tgcn.xml/bin ← OpenVINO IR (generated by convert_to_ir.bat)
│   ├── labels.json            ← 2000-word label map
│   └── readme.md              ← Model documentation
│
├── model3/                    ← LSTM ASL Recognition (250 signs)
│   ├── model.json             ← REQUIRED — model configuration
│   ├── model.onnx             ← ONNX weights (NOT convertible to IR)
│   ├── labels.json            ← 250-sign label map
│   └── README.md              ← Model documentation
│
└── _active_model.txt          ← Auto-generated, persists selection
```

### Intel OpenVINO Acceleration

Models 1 and 2 are automatically loaded through OpenVINO IR for Intel-optimized
CPU inference (LATENCY performance hint + compiled model caching). Model 3 cannot
be converted (unsupported LSTM Loop operator) and uses ONNX Runtime instead.

To convert or reconvert:
```bash
convert_to_ir.bat               # Converts all compatible models
convert_to_ir.bat --check-only  # Just report which can be converted
convert_to_ir.bat --force       # Rebuild IR even if files exist
```

The `.xml` + `.bin` files are placed alongside the ONNX files in each model folder.
The model loader automatically prefers IR over ONNX when both are present.

## Adding a New Model

1. Create a new folder: `models/sign/model3/`
2. Place your model weights file (`.onnx`, `.h5`, `.keras`, or `.tflite`)
3. Create a `model.json` — use one of the templates below:

### Template: Single-Frame Fingerspelling

```json
{
  "name": "Your Model Name",
  "model_file": "your_model.onnx",
  "type": "fingerspelling",
  "labels": "ABCDEFGHIKLMNOPQRSTUVWXY",
  "input": {
    "landmark_source": "mediapipe_hands",
    "max_hands": 1,
    "input_shape": [1, 21, 3],
    "use_dimensions": "auto",
    "normalize": "min_max"
  },
  "inference": {
    "type": "single_frame",
    "confidence_threshold": 0.60,
    "backend": "onnx"
  },
  "postprocess": {
    "misrecognition_fixes": true,
    "spell_correction": true
  }
}
```

### Template: Sequence Word-Level (Holistic)

```json
{
  "name": "Your Word Model",
  "model_file": "your_model.onnx",
  "type": "word_level",
  "labels": "labels.json",
  "input": {
    "landmark_source": "mediapipe_holistic",
    "max_hands": 2,
    "input_shape": [1, 55, 100],
    "use_dimensions": 2,
    "normalize": "none"
  },
  "inference": {
    "type": "sequence",
    "confidence_threshold": 0.30,
    "sequence_length": 50,
    "backend": "onnx"
  },
  "postprocess": {
    "misrecognition_fixes": false,
    "spell_correction": false
  }
}
```

4. Restart the backend — the model will be auto-discovered
5. Switch to it in Settings → Model Selection

## Required Fields

Only `name` and `model_file` are required. Everything else has defaults
that match the current PointNet model.

## Supported Model Types

| Type | Landmark Source | Inference | Points | Runtime | Example |
|------|----------------|-----------|--------|---------|---------|
| `fingerspelling` | `mediapipe_hands` | `single_frame` | 21 hand | OpenVINO IR | Model 1 — PointNet |
| `word_level` | `openpose` or `mediapipe_holistic` | `sequence` | 55 upper-body | OpenVINO IR | Model 2 — WLASL Pose-TGCN |
| `word_level` | `mediapipe_holistic` | `sequence` | 543 holistic | ONNX Runtime | Model 3 — LSTM (250 signs) |

## Key Configuration Fields

| Field | Purpose | Options |
|-------|---------|---------|
| `input.landmark_source` | Landmark extraction backend | `mediapipe_hands`, `mediapipe_holistic`, `openpose` |
| `inference.type` | Frame vs. temporal classification | `single_frame`, `sequence` |
| `inference.sequence_length` | Frames to buffer (sequence only) | Integer (e.g., 50) |
| `input.normalize` | Landmark normalization method | `min_max`, `wrist_relative`, `frame`, `none` |

### OpenPose Note (Model 2)

Model 2 can use OpenPose for higher fidelity. Set `OPENPOSE_DIR` so the backend
can load OpenPose Python bindings and model files.

> **Note**: OpenPose is very CPU-intensive (~91% on typical systems, 1-2 FPS).
> A replacement using Intel OpenVINO Human Pose Estimation is planned. See
> `.kiro/model2plan.md` for details.

## Legacy Support

If you have model files directly in `models/sign/` (not in a subfolder),
the registry will auto-migrate them to `models/sign/model1/` on first run.
